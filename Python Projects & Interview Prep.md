## 100 ESSENTIAL PYTHON INTERVIEW QUESTIONS (by category — study, don't just memorize)

**Fundamentals (1–15):** Mutable vs immutable types · `is` vs `==` · deep copy vs shallow copy · Python's memory model (everything is an object) · `*args`/`**kwargs` · variable scope (LEGB rule) · GIL and its implications · Python 2 vs 3 key differences · `pass` vs `continue` vs `break` · truthy/falsy values · string interning · f-strings vs `.format()` vs `%` · `None` vs `False` vs `0` · walrus operator `:=` · duck typing.

**Data Structures (16–30):** list vs tuple vs set vs dict (when to use each) · how dict hashing works · time complexity of common list/dict/set ops · list comprehension vs generator expression · shallow vs deep nested structures · `sorted()` vs `.sort()` · `Counter` vs manual counting · `defaultdict` use cases · `namedtuple` vs `dataclass` vs regular class · set operations (union/intersection/difference) · slicing mechanics · unpacking (`a, *b = [...]`) · dict merging (`|` operator, 3.9+) · frozensets · why dict keys must be hashable.

**Functions (31–40):** default mutable argument pitfall (`def f(x=[])`) · closures and late binding · decorators — how they actually work · `*args`/`**kwargs` unpacking in calls · recursion depth limits · lambda limitations vs named functions · first-class functions concept · `functools.wraps` purpose · memoization (`lru_cache`) · pure functions vs side effects.

**OOP (41–55):** `__init__` vs `__new__` · class vs static vs instance methods · MRO (Method Resolution Order) and `super()` · abstract base classes · operator overloading (`__add__`, etc.) · `__str__` vs `__repr__` · property decorators (`@property`) · composition vs inheritance · multiple inheritance & diamond problem · `__slots__` purpose · metaclasses (conceptual) · encapsulation conventions (`_`, `__`) · dataclasses vs regular classes · class variables shared-state pitfall · SOLID principles applied to Python.

**Exceptions & Files (56–63):** try/except/else/finally execution order · custom exception design · context managers (`with`) internals · handling multiple exception types · re-raising exceptions (`raise` vs `raise from`) · file modes (`r`, `w`, `a`, `rb`) · JSON vs pickle trade-offs (security, portability) · `pathlib` vs `os.path`.

**Intermediate (64–78):** iterators vs iterables · generator vs list memory trade-off · `yield` vs `return` · decorators with arguments · context manager via `contextlib.contextmanager` · regex greedy vs non-greedy · `itertools.groupby` gotchas (needs sorted input) · `functools.reduce` use cases · shallow understanding check: what does `__call__` do · monkey patching (what/why/risks) · GIL vs true parallelism · threading vs multiprocessing vs asyncio (core interview favorite) · async/await mechanics · coroutines vs threads · event loop basics.

**Testing/Quality (79–85):** unittest vs pytest · mocking external API calls in tests · fixtures in pytest · test coverage meaning/limits · why bare `except:` is bad · linting vs formatting distinction · type hints — do they affect runtime.

**Databases/APIs (86–93):** SQL injection prevention (parameterized queries) · ORM vs raw SQL trade-offs · REST principles · idempotency in APIs (GET vs POST vs PUT) · status codes (200/201/400/401/404/500 meanings) · JWT structure and stateless auth · rate limiting strategies · connection pooling purpose.

**System Design/Practical (94–100):** how would you design a URL shortener · how would you design a rate limiter · how would you scale a Flask app · caching strategies (in-memory vs Redis) · designing a job queue · handling a memory leak in production · designing for idempotent retries.

**Where to find exact problems:** NeetCode 150 list (free, curated, matches the categories above almost exactly) — the single best free structured problem list available.

### LeetCode Roadmap
Easy (build confidence, ~40 problems) → Medium (bulk of interview prep, ~50 problems) → Hard (only after Medium is comfortable, ~10 problems). Follow the **NeetCode 150** or **Blind 75** list rather than solving randomly.

### HackerRank Roadmap
"10 Days of Python" (fundamentals) → "Problem Solving (Basic)" → "Problem Solving (Intermediate)" → domain-specific tracks (SQL, if pursuing data roles).

### Codewars Roadmap
8kyu → 7kyu → 6kyu (this range covers 90% of interview-relevant fundamentals) → 5kyu once comfortable with intermediate Python. Use kata as daily warm-ups, not primary prep.

### Project Euler Roadmap
Problems 1–20 (math + basic loops/logic) → 21–50 (introduces need for optimization, good for learning Big-O intuition) → beyond 50 only if you enjoy math-heavy problem solving — it's a supplement, not core interview prep (LeetCode/NeetCode matters more for job interviews).
